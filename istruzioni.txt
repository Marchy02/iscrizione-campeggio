# Bug report – Sistema iscrizioni campeggio (Supabase + frontend statico)

Questo documento descrive i problemi attuali del progetto e cosa va sistemato.
Serve come riferimento tecnico per intervenire sul codice.

---

## Contesto progetto

* Backend: Supabase (Postgres + RPC)
* Frontend: HTML + JS statico (GitHub Pages)
* File principali:

  * `turno.html`
  * `admin.html`
  * `app.js`
  * funzioni RPC già funzionanti (`crea_iscrizione`, `get_turno_stats`, ecc.)

---

## Problemi da risolvere

### 1. Errore JS in admin panel all’avvio

**Errore console:**

```
admin.html:116 Errore init: ReferenceError: setupConditionalFields is not defined
    at init (admin.html:112:9)
```

**Descrizione:**

Nel file `admin.html`, durante l’esecuzione della funzione `init()`, viene chiamata:

```js
setupConditionalFields();
```

ma questa funzione **non è definita nel file admin.html** (esiste solo in `turno.html`).

**Comportamento attuale:**

* L’admin panel genera errore JS all’apertura
* Parte del codice successivo non viene eseguito correttamente

**Fix richiesto:**

Una delle seguenti soluzioni:

* Rimuovere la chiamata a `setupConditionalFields()` da `admin.html`

oppure

* Implementare una funzione vuota di compatibilità in `admin.html`:

```js
function setupConditionalFields() {}
```

---

### 2. Bug form maggiorenne / minorenne

**File:** `turno.html`

**Descrizione:**

Il form ha una checkbox:

> "Il partecipante è maggiorenne"

Problemi attuali:

* All’apertura della pagina, se NON è maggiorenne, il form dei dati del genitore deve apparire
* Se l’utente spunta "maggiorenne", il form dei genitori **non scompare sempre correttamente**

**Fix richiesto:**

Gestione completa dello stato iniziale + evento `change` sul checkbox:

* se `checked === true` → nascondere sezione genitori + rimuovere required
* se `checked === false` → mostrare sezione genitori + required attivi

Implementare funzione unica tipo:

```js
function aggiornaStatoGenitore() { ... }
```

chiamata:

* all’avvio
* ad ogni `change`

---

### 3. Statistiche non visibili nel pannello admin

**File:** `admin.html`

**Backend:** funzione RPC `get_turno_stats(p_turno_id)` restituisce JSON

Esempio risposta:

```json
{
  "confermati": 3,
  "lista_attesa": 1,
  "posti_totali": 30,
  "posti_occupati": 3,
  "posti_disponibili": 27
}
```

**Problema:**

Nel pannello admin le statistiche non vengono mostrate o restano vuote.

**Cause probabili:**

* parsing errato della risposta (usare `stats.campo`, NON `stats[0].campo`)
* errore JS precedente (vedi bug #1) che interrompe l’esecuzione
* elementi DOM non trovati o id errati

**Fix richiesto:**

Verificare che:

```js
const { data: stats } = await supabase.rpc('get_turno_stats', ...)
```

venga poi usato come:

```js
stats.confermati
stats.lista_attesa
stats.posti_disponibili
```

E che gli elementi DOM esistano:

* `#stat-confermati`
* `#stat-attesa`
* `#stat-posti`
* ecc.

---

### 4. Campi allergie / patologie: textarea non appare

**File:** `turno.html`

**Descrizione:**

Ci sono due checkbox:

* "Ha allergie"
* "Ha patologie / medicinali"

Quando vengono selezionate:

* dovrebbe apparire un textarea per la descrizione

**Problema attuale:**

* checkbox funziona
* ma il campo testo NON appare

**Cause probabili:**

* `getElementById` errato
* `style.display` non aggiornato
* funzione JS non chiamata all’avvio
* ID HTML non coerenti con JS

**Fix richiesto:**

Implementare logica robusta:

```js
if (checkbox.checked) {
  section.style.display = 'block'
  textarea.required = true
} else {
  section.style.display = 'none'
  textarea.required = false
  textarea.value = ''
}
```

con:

* evento `change`
* chiamata iniziale all’avvio pagina

## File SQL attualmente in uso

Questi sono i file SQL correnti del progetto (backend Supabase):

### 1. `01-schema.sql`

Contiene:

* definizione tabelle: `turni`, `iscrizioni`, `email_queue`

* indici
* trigger `updated_at`
* trigger per ricalcolo `posti_occupati`

  * `riordina_lista_attesa(p_turno_id BIGINT)`
  * `promuovi_da_lista_attesa(p_turno_id BIGINT)`

Ruolo: struttura completa del database.

---

### 2. `02-functions.sql`

Contiene le RPC principali:

* `crea_iscrizione(...) RETURNS json`
* `cancella_iscrizione(p_iscrizione_id BIGINT) RETURNS json`
* `promuovi_iscrizione(p_iscrizione_id BIGINT) RETURNS json`
* `get_turno_stats(p_turno_id BIGINT) RETURNS json`

Include:

* `SECURITY DEFINER`
* gestione lista d’attesa
* inserimento automatico in `email_queue`
* `GRANT EXECUTE` per anon / authenticated

Ruolo: tutta la logica applicativa lato database.

---

### 3. `03-policies.sql`

Contiene:

* abilitazione RLS su tutte le tabelle
* policy:

  * lettura pubblica solo turni attivi
  * blocco insert diretti su `iscrizioni`
  * accesso admin tramite `user_metadata.role = 'admin'`
  * accesso controllato a `email_queue`

Ruolo: sicurezza e separazione frontend / backend.

---

### 4. `04-seed.sql`

Contiene:

* inserimento turni iniziali di esempio

Nessun inserimento su `iscrizioni` o `email_queue`.

Ruolo: dati iniziali per test e deploy.

---

## Nota importante per chi lavora sul backend

* Tutte le funzioni usano `BIGINT` per gli ID
* Evitare di creare funzioni con lo stesso nome ma tipo `INTEGER`
* In caso di modifiche alle RPC:

```sql
DROP FUNCTION nome_funzione(tipo);
```

prima di ricrearle.

* Dopo ogni modifica alle funzioni RPC:

```sql
NOTIFY pgrst, 'reload schema';
```

oppure usare il pulsante **Reload schema cache** da Supabase dashboard.
